Lecture 8

Combinational functional blocks: multiplexer, two's complement, adder, ALU

Ready-made "bricks" bigger than a gate. The multiplexer as a switch and as a universal logic function, negative numbers in two's complement, the adder and the arithmetic logic unit.

📋 Quick summary

✚ = added by the site author — not in the slides or the lecture recording

A functional block

A combinational functional block is a combinational circuit with n inputs and m outputs. A Boolean function is its special case — with one output.

Examples: switching blocks (multiplexers, demultiplexers, decoders, code converters) and arithmetic blocks (adders, comparators).

Multiplexer (MUX)

A multiplexer has:

  • n address (select) inputs,
  • N = 2n data inputs,
  • one output,
  • an enable input (usually: e = 1 — working, e = 0 — off).

It works as a switch: the output receives the signal from the data input whose number is given on the address inputs.

🧒In plain words

A multiplexer is a TV remote. The data inputs are the channels, the address inputs are the channel number pressed on the remote, and the output is what you see on the screen. (This comparison comes from the lab materials.)

  • The number of data inputs grows exponentially, so large multiplexers are not built directly — they are assembled from smaller ones (cascaded).
  • A bus multiplexer switches whole words (e.g. 4-bit buses A and B), not single bits.

Demultiplexer (DMUX) and decoder

A demultiplexer works the other way round: one data input, n address inputs and N = 2n outputs. The input signal goes to the output indicated by the address.

A decoder is a demultiplexer whose input is permanently 1: it converts a binary number into the "1 of N" code — exactly one output is active.

The multiplexer as a logic function

A multiplexer can implement any Boolean function. The lecture example: y = Σ(1, 7, 11, 13, 14, 15), variables x3 x2 x1 x0.

Way 1: a multiplexer with 4 address inputs (16 data inputs)

All four variables go to the address inputs. Data inputs number 1, 7, 11, 13, 14, 15 get 1, the rest get 0. The multiplexer simply "reads the truth table".

Way 2: a multiplexer with 3 address inputs (8 data inputs)

Three variables go to the address, and the fourth — to the data inputs. For each address compare the two values of the function (for the fourth variable equal to 0 and to 1):

Number codes

NKB

value = Σ 2i · bi

Bits are numbered from zero on the right; the weights are 1, 2, 4, 8, 16, 32, 64, 128. N bits give 2N different values (8 bits: 0…255).

Sign–magnitude and ones' complement

  • ZM: −24 = 1 0011000, 118 = 0 1110110. Range ±(2N−1 − 1). Drawback: two zeros (+0 and −0).
  • U1: positive numbers as in ZM; negative ones — with the magnitude bits inverted: −86 is 11010110 in ZM and 10101001 in U1. Two zeros as well.

Two's complement (U2) — the one computers actually use

The top bit has a negative weight, the others positive:

value = −2N−1 · bN−1 + Σ 2i · bi
  • Range: from −2N−1 to 2N−1 − 1 (8 bits: −128…127; 4 bits: −8…7).
  • Zero has only one representation; the code is complete (2N values).
  • Positive numbers look the same as in NKB.
  • The top bit tells the sign: 1 = negative.

4-bit examples from the lab materials: 1111 = −8+4+2+1 = −1, 1000 = −8, 0111 = 7.

The opposite number: invert all the bits and add 1.

7 = 00000111  →  11111000  →  +1  →  11111001 = −7

🧒In plain words

A car odometer that you wind back. From 0000, going back one gives 9999 — and we agree that 9999 means "−1". Two's complement is the same thing in binary: 0000 − 1 = 1111, i.e. −1.

Adding and subtracting in U2

  • Add exactly as in NKB, ignoring the signs.
  • Ignore the carry out of the top bit.
  • Subtraction is adding the opposite number: a − b = a + (−b). So negation and an adder are enough.

Overflow can only happen when adding two positive or two negative numbers whose result "does not fit". You can see it in the sign: two positives gave a negative, or the other way round.

Hardware detection: look at the two carries at the top bit — the one coming in (CIN) and the one going out (COUT). There is overflow if and only if they differ:

OFL = CIN ⊕ COUT

Other U2 traps: the range is asymmetric (for 8 bits −128 exists, +128 does not), and incrementing 127 gives −128.

Numbers with a fraction

  • Fixed point: we agree that some bits are the integer part and the rest the fraction. E.g. 5 + 3 bits in U2 — weights: −16, 8, 4, 2, 1, ½, ¼, ⅛. Then 11001110 = −16 + 8 + 1 + ½ + ¼ = −6¼. Range: from −16 to 15⅞, precision ⅛.
  • Floating point: mantissa · 2exponent.

With a finite number of bits some numbers are stored with an error, and irrational ones always are.

The adder

Long addition in binary:
7601001100
+ 11801110110
= 19411000010

At each position three bits are added: ai, bi and the carry ci from the previous position; we get a sum bit and a carry onward. This is done by a one-bit (full) adder:

y = a ⊕ b ⊕ c0  c = ab + ac0 + bc0

An n-bit adder is a cascade of one-bit adders: the carry out of one goes into the next.

For unsigned numbers a carry out of the top bit (cn = 1) means the result did not fit: 152 + 118 = 270 on 8 bits gives 00001110 (= 14) and a carry of 1. It can be treated as an extra, top bit of the result.

✚From the site author (not in the lecture)

The slide has a typo in this addition example: the second operand is labelled "188", but 01110110 is 118 (76 + 118 = 194).

Comparator and ALU

A comparator compares two n-bit numbers and tells whether A < B, A = B or A > B.

An ALU (Arithmetic Logic Unit) is a combinational circuit that performs arithmetic and logic operations on two numbers (or on one).

  • A, B — input data,
  • F — operation code (what to compute),
  • R — the result,
  • D — status, i.e. flags (e.g. result is zero, overflow).

The simplest implementation: all operations are computed at the same time, and a multiplexer controlled by the code F selects which result goes to the output.

🎓Lab tasks (from the slide)

  1. Implement a given function with a multiplexer with four address inputs.
  2. The same with a multiplexer with three address inputs and at most one inverter.
  3. A circuit detecting overflow for 4-bit numbers in U2.
  4. A 4-bit ALU with four operations (on the slide: 00 ADD, 01 NEG, 10 XOR, 11 AND) and flags Z (result zero) and C (overflow).

The essentials of this topic — for a fast recap before the lab.

Multiplexer

  • n address inputs → 2n data inputs; output = the data input whose number is on the address.
  • Function on a 16:1 MUX: feed 1 to the inputs listed in Σ, 0 to the rest.
  • Function on an 8:1 MUX: 3 variables to the address, the fourth "free" one x. For each address compare y at x = 0 and x = 1:
y(x=0), y(x=1)0, 01, 10, 11, 0
feed the input01xx
  • Free x3: row pairs (k, k+8). Free x0: pairs (2k, 2k+1).
  • DMUX: one input → the output indicated by the address. Decoder: binary → 1 of N.

Two's complement (N bits)

  • Weight of the top bit: −2N−1. Range: −2N−1 … 2N−1−1 (4 bits: −8…7; 8 bits: −128…127).
  • Opposite number: invert the bits, add 1.
  • Add as in plain binary; ignore the carry out of the MSB. Subtraction: a + (−b).
  • Overflow = CIN ⊕ COUT of the top bit (positive + positive = negative, or vice versa).

Adder and ALU

  • Full adder: y = a ⊕ b ⊕ c0, c = ab + ac0 + bc0. An n-bit adder = a cascade.
  • Half adder (no carry in) ✚: s = a ⊕ b, c = ab.
  • ALU: A, B — data; F — operation code; R — result; D — flags. All operations computed at once, a MUX picks the result.
  • Other codes: BCD (digit → 4 bits), ZM (sign bit + magnitude), U1 (bits inverted), Gray, 1 of N.
