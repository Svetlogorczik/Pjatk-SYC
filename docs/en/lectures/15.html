Lecture 15

Assembly language and computer architecture (MIPS)

The language a processor really "speaks". Instructions, registers, memory, branches and loops in MIPS assembly — and what such an instruction looks like as 32 zeros and ones.

📋 Quick summary

✚ = added by the site author — not in the slides or the lecture recording

The computer's language

  • The words of a computer's language are instructions, and its vocabulary is the instruction set.
  • All programs running on a given computer use the same instruction set.
  • Instructions are encoded as binary numbers — this is machine language.
  • It is more convenient to write them symbolically — this is assembly language.

One line of high-level code and its MIPS equivalent:

  • add is the mnemonic — it says which operation to perform,
  • b and c are the source operands, a is the destination operand (the result).
  • A comment starts with # and runs to the end of the line.

A more complex expression must be split into several instructions: a = b + c − d becomes sub t, c, d and add a, b, t.

🧒In plain words

Assembly is a recipe broken down into the smallest possible steps: "take an egg", "crack the egg", "pour it into the bowl". No "make an omelette" — the processor only knows such single moves.

Registers

Instructions work on registers — fast cells inside the processor. MIPS has 32 of them (the Register File). Their names start with $.

RegistersNumbersWhat for
$00always contains zero
$v0–$v12–3function return value
$a0–$a34–7function arguments
$t0–$t78–15temporary — intermediate results
$s0–$s716–23saved — program variables
$sp29stack pointer
$ra31return address of a function

Memory

There are only 32 registers, so most data lives in memory. Two instructions move data:

  • lw (load word) — load a word from memory into a register,
  • sw (store word) — store a word from a register into memory.

The address is written as offset(base register): lw $s3, 8($t0) means "take the word at address $t0 + 8".

  • MIPS memory is byte-addressed: every byte has its own address.
  • A word is 32 bits = 4 bytes, so the addresses of successive words are multiples of 4: 0, 4, 8, 12…

Big-endian and little-endian

These are two ways of numbering the bytes in a word. In big-endian byte number 0 is at the "big" (most significant) end; in little-endian — at the "little" (least significant) end.

Constants (immediates)

A constant written directly in the instruction is called an immediate — no register or memory access is needed to get it. addi (add immediate) is used for that.

Machine language: three formats

Every MIPS instruction is exactly 32 bits. There are three formats:

FormatFields (number of bits)What for
R (register)op (6) · rs (5) · rt (5) · rd (5) · shamt (5) · funct (6)operations on three registers
I (immediate)op (6) · rs (5) · rt (5) · imm (16)two registers and a 16-bit constant
J (jump)op (6) · addr (26)jumps

R-type

  • rs, rt — source registers, rd — destination register,
  • all R-type instructions have op = 0; the funct field decides which operation it is,
  • shamt — by how many bits to shift (shift instructions only).

🔎The lecture example: add $t0, $s4, $s5

In assembly the destination register comes first; in machine code the field order is different: rs, rt, rd.

Fieldoprs ($s4)rt ($s5)rd ($t0)shamtfunct (add)

Together: 0000 0010 1001 0101 0100 0000 0010 0000 = 0x02954020. The easiest way is to write it in binary first and then group the bits in fours into hexadecimal digits.

J-type

Used only for jumps: a 6-bit opcode and a 26-bit address.

The other way: from machine code to assembly

The first 6 bits are the opcode — it tells how to read the rest.

🔎The lecture example

0x2237FFF1 = 001000 10001 10111 1111111111110001 → op = 8 (addi), rs = 17 ($s1), rt = 23 ($s7), imm = −15 → addi $s7, $s1, -15

0x02F34022 = 000000 10111 10011 01000 00000 100010 → op = 0 (R-type), rs = 23 ($s7), rt = 19 ($s3), rd = 8 ($t0), funct = 34 (sub) → sub $t0, $s7, $s3

The program in memory

A machine-language program is simply a sequence of binary numbers stored in memory — just like data. The program counter PC points to the instruction being executed.

Logic instructions and shifts

  • Logic: and, or, xor, nor — work bit by bit on two registers. Versions with a constant: andi, ori.
  • Shifts: sll (logical left), srl (logical right), sra (arithmetic right).
  • A shift by n bits is a multiplication or division by 2n: sll $t0, $t0, 3 multiplies by 8.

Branches and jumps

A computer's power lies in its ability to make decisions.

InstructionMeaning
beq rs, rt, labelbranch if the registers are equal
bne rs, rt, labelbranch if they are not equal
j labeljump unconditionally
jal labeljump and remember the return address (function call)
jr $rajump to the address in a register (return from a function)

A label is a name for a place in the program; it ends with a colon.

Arrays

An array is consecutive memory cells. The base address is the address of array[0]. Each element (word) takes 4 bytes, so array[1] is 4 bytes further, array[2] — 8 bytes further, and so on.

A 32-bit address does not fit in one instruction, so it is loaded in two steps: lui sets the upper 16 bits, ori the lower ones.

Functions and the stack

Functions let you reuse the same code. The MIPS convention:

  • arguments are passed in registers $a0–$a3,
  • the result comes back in register $v0,
  • jal jumps to the function and saves the return address in $ra; jr $ra returns.

The stack is a memory area for a function's local variables (and extra arguments). It works on the LIFO principle — the last item pushed is the first popped. The stack pointer $sp shows the top; the stack starts at a high address and grows downward.

🧒In plain words

The stack is a stack of plates: you put one on top and take one from the top. A function pushes onto it what it must preserve and pops it before returning — in reverse order.

Other topics

  • Floating point: MIPS has 32 separate registers $f0–$f31 and supports the IEEE standard (single and double precision).

From source code to a running program

🪜Step by step

  1. Compilation — the compiler translates high-level code into assembly.
  2. Assembly — the assembler turns the code into an object file with machine language; it assigns addresses to instructions and labels.
  3. Linking — the linker combines object files (including those from libraries) into one executable.
  4. Loading — the operating system reads the executable from disk into memory and starts the program.

MIPS versus x86

FeatureMIPS (RISC)x86 (CISC)
Registers32 general-purpose8, some with restrictions
Operands3 (2 sources, 1 destination)2 (one is both source and destination)
Where operands can beregisters or immediatesregisters, immediates or memory
Operand size32 bits8, 16 or 32 bits
Condition codes (flags)noyes (the EFLAGS register)
Instructionssimplesimple and complicated
Encodingfixed, 4 bytesvariable, 1–15 bytes

Almost all personal computers use x86 processors — an example of CISC.

Formats (32 bits)

Fields
Rop(6)=0 · rs(5) · rt(5) · rd(5) · shamt(5) · funct(6)

  • funct: add = 32, sub = 34, and = 36, or = 37, slt = 42. op: addi = 8, lw = 35, sw = 43, beq = 4.
  • Decoding: hex → binary → the first 6 bits (opcode) → split into fields.

Memory

  • Byte addressing; word = 4 bytes → word addresses: 0, 4, 8… array[i] = base + 4·i.
  • Stack: LIFO, $sp, grows downward. Function: arguments $a0–$a3, result $v0, jal / jr $ra.
  • Compiler → assembler → linker → loader.
  • MIPS = RISC (simple, 3 operands, 4 bytes); x86 = CISC (2 operands, variable length).
