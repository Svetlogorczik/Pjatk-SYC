Lab 8

Minimising Boolean functions: the Karnaugh map, NAND and NOR implementations

The same circuit can be built from fifteen gates or from four. In this class you learn to do the latter: truth table → Karnaugh map → shortest formula → a schematic made of NAND gates only (or NOR gates only).

📋 Quick summary Lecture for this lab: Lecture 7 →

✚ = added by the site author — not in the slides or the lecture recording

What you need to know before the class

  • The Karnaugh map, Gray code, the merging rule — lecture 7 (Quick summary).
  • Using Logisim and the NAND bricks — lab 7.

There are two tasks in class (from the lecture slide): a four-variable function assigned by the instructor — its minimal form on NAND gates; and the control of the robot from the previous class — on NOR gates only.

The recipe in five steps

🪜Step by step

  1. Truth table — list the combinations for which the function is 1.
  2. Karnaugh map — draw the grid, label the columns (and rows) in the order 00, 01, 11, 10 and write in the ones.
  3. Groups — outline the ones with rectangles of 1, 2, 4 or 8 cells. Groups as large as possible, as few as possible, they may overlap, the map "wraps around" at the edges.
  4. Formula — for each group write only the variables that do not change inside it (0 → negated, 1 → plain). Join the groups with pluses.
  5. Convert to NAND — replace every AND gate and the final OR with NAND. Done.

⚠️The most common mistake

The map columns are 00, 01, 11, 10 — not 00, 01, 10, 11. The last two columns are "swapped" so that neighbouring cells differ in one bit only. A slip here ruins everything that follows.

🧒In plain words

The red group joins the first and the last column. That is not a mistake: imagine the map glued around a tin can — the left and right edges touch each other.

Converting to NAND gates

Two tools: double negation (Q = Q — changes nothing) and De Morgan's law (P + Q = P·Q).

For the right motor, step by step:

RM = a + b·c = a + b·c = a · b·c

That is: RM = a NAND (~b NAND c). The left motor works the same way:

LM = b·c · a·c · a·b

That is: LM = (~b NAND ~c) NAND (a NAND ~c) NAND (a NAND ~b) — three two-input NAND gates and one three-input gate.

💡A shortcut worth remembering

A "sum of products" formula is converted to NAND without any calculation: every AND → NAND, the final OR → NAND. The only trap: a term that is a single variable (like a in RM) enters the last gate negated (i.e. as a).

🪜Step by step

  1. In Logisim insert four inputs a, b, c, d and an output f.
  2. Make the negations: four NAND gates with tied inputs (or NOT, if the instructor allows it).
  3. Insert three "first-floor" NAND gates — one per group. Set the right number of inputs for them (2, 3, 3).
  4. Insert one "second-floor" NAND gate with three inputs and connect the outputs of the previous three to it.
  5. Check all 16 combinations. Fastest: Project → Analyze Circuit and compare the result column with the Σ list.

❓Self-check

Count the ones. The function has 8 ones; the groups have 4 + 2 + 2 = 8 cells and none repeats — it matches. If the sum of cells in the groups is smaller than the number of ones, some one is not covered.

Class task 2: implementation on NOR only

For NOR gates the recipe is a mirror image: we group the zeros, not the ones.

🪜Step by step

  1. On the map outline groups of zeros (the same rules: 1, 2, 4, 8 cells).
  2. For each group write the sum of the variables that do not change — but the other way round than for ones: 0 → plain, 1 → negated.
  3. Multiply the sums together. This is the "product of sums" form.
  4. Replace every OR and the final AND with NOR. A single variable enters the last gate negated.

Minimise f(a,b,c) = Σ(0, 2, 4, 5, 6) and write it on NAND.

📝4. The same function on NOR

For the function of task 3 group the zeros and write the NOR implementation.

✅Show solution

Zeros: 3, 4, 6, 7, 11, 12, 13, 14, 15.

  • The whole row 11 (12, 13, 15, 14): a = 1, b = 1 → (a + b)
  • The four 4, 6, 12, 14 (across the edge): b = 1, d = 0 → (b + d)
  • The whole column 11 (3, 7, 15, 11): c = 1, d = 1 → (c + d)

f = (a + b)·(b + d)·(c + d)

On NOR: (~a NOR ~b) NOR (~b NOR d) NOR (~c NOR ~d).

📝5. Why not three?

The map has three ones next to each other in one row. Why may you not make one group of them?

✅Show solution

A group must have 1, 2, 4 or 8 cells, because only then does the variable that changes inside it take both values with every combination of the others — and so it disappears (x + x = 1). Three cells do not give such a pair. The solution: two pairs that overlap on the middle cell.

💡What costs points most often

  • Columns in the order 00, 01, 10, 11 instead of 00, 01, 11, 10.
  • Overlooked groups "across the edge" and the four corners.
  • Groups too small (two pairs instead of one four) — the circuit works but is not minimal.
  • With NAND: a single variable fed to the last gate without inverting it.
  • With NOR: grouping ones instead of zeros, or forgetting to swap the negations (0 → no bar).
